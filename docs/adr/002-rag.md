# ADR 002 — RAG設計（AI秘書の知識基盤）

**日付**: 2026-06-27
**ステータス**: 決定済み

---

## 背景

AI秘書機能（建築専門知識の相談・契約書雛形生成）において、専門知識・判例・社内ナレッジを回答に反映させるためRAGが必要。

## 決定事項

### ベクトルDB: pgvector（PostgreSQL拡張）

- PostgreSQLに`pgvector`拡張を追加してベクトル検索を実現
- 別途ベクトルDBを立てず、既存のPostgreSQLで完結させる

### AIモデル: Claude API

- 埋め込み（Embedding）と生成どちらもClaude APIを使用
- 建築専門知識・判例をベクトル化してpgvectorに保存

### RAGの流れ

```
ユーザーの質問
  → 質問をベクトル化（Claude Embeddings）
  → pgvectorで類似ドキュメント検索
  → 検索結果 + 質問をClaudeに渡す
  → 回答生成
```

## 不採用の選択肢

### Pinecone / Weaviate 等の専用ベクトルDB

- インフラが増えて管理コストが上がる
- PostgreSQLで足りる規模感なので不採用

### OpenAI Embeddings

- 既にClaude APIを使うため、一本化してシンプルにする

## 注意事項

- **契約書雛形生成には必ず弁護士確認を促す注意書きを表示する**（法的リスク回避）
- RAGに投入するドキュメントは管理者が管理する
