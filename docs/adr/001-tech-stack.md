# ADR-001: テックスタック選定

**日付**: 2026-06-18  
**ステータス**: 決定済み

---

## 背景

公共工事の入札情報を管理・閲覧するWebシステムを構築する。  
主なアクセス環境はLINEの内蔵ブラウザ（WebView）。  
将来的にスクレイピング機能を組み込む予定がある（Pythonによる実装はすでに存在する）。

---

## 決定事項

### フロントエンド: Next.js + shadcn/ui + Tailwind CSS

**採用理由:**
- LINEブラウザはSSR（サーバーサイドレンダリング）との相性が良い。HTMLをサーバーで生成するためJSに依存しない
- Next.jsはSPAではなくSSRがデフォルト。Laravelに近い考え方で馴染みやすい
- shadcn/uiによりコンポーネントが統一される。TailwindだけではページごとにUIがバラつく問題があった
- Next.jsのAPI Routesが将来のスクレイピング連携バックエンドとしても機能できる

**不採用の選択肢:**
- **Express + EJS**: テンプレートエンジンだけではデザインの統一が難しい
- **React (SPA)**: クライアントサイドJS依存になりLINEブラウザで不安定になりうる
- **Express + Tailwind CSS (コンポーネントライブラリなし)**: Tailwindだけでは各ページで書き方がバラつき、結果的に統一感が失われた（他プロジェクトで経験済み）

### スクレイピング: Python (既存)

**採用理由:**
- すでに `scraper/` にPythonの実装が存在する（`login.py`, `list_scraper.py`, `detail_scraper.py`）
- PythonはスクレイピングエコシステムがNode.jsより成熟している
- Next.jsフロントエンドとはAPI経由で連携する構成とする

### インフラ: nginx + PM2 (Ubuntu VPS)

- nginx: リバースプロキシ。Next.jsの3000番ポートを80/443に転送
- PM2: Node.jsプロセス管理。サーバー再起動時の自動起動も担う

---

## 教訓

- **Tailwind CSS単体ではデザイン統一に不十分**。必ずdaisyUI / shadcn/ui などのコンポーネントライブラリを併用すること
- Claudeへの指示時は「shadcn/uiのコンポーネントを使って」と明記する。そうしないと毎回ゼロからCSSを書いてページごとにデザインがバラつく
